# Crosshair and companions

- **Crosshair HUD** — one HUD with two modes (assist when a hostile is the hard target/under the crosshair, otherwise interact for `softinteract`: cursor icon, name, interact key; also another player under the crosshair once aimed at for `PLAYER_DWELL` (1 s) out of combat: portrait in the masked icon slot, class-coloured name, same key, which opens their menu via `CM.GetPlayerUnderCrosshair` from `PlayerMenu.lua`; secret GUIDs fail closed), all under `Core/Crosshair/AssistedHighlight/`: `Keybinds` → `Interact` (softinteract identity/name/key/range) → `Motion` (ProcLoop/glow/fade) → `CastProgress` (swipe/break) → `Feedback` (press/pulse + façade; Attach also binds CastProgress) → `Assist` (chrome + public APIs).
- **FocusNameplateMarker** — when `CM.DB.global.showTargetLockMarker` (default on): Target Lock makes the center reticle a static base-colored idle texture (`global.crosshairTargetLockId`, default `crosshairDot`; the mounted reticle uses `crosshairMountedId`; unreactive) for as long as focus exists (even with no nameplate); a hostile-red hit marker (the `support` color while Support Mode is on, where the lock is an ally; only a public "can attack" keeps it red there) reverse-arrives onto the plate (scale/alpha), then color-pulses while settled and, every `PULSE_INTERVAL` (4 s), sends out a ghost copy (child frame `marker.pulse`) that swells and fades like the reticle's mode-swap; parented to the plate root with ignore-parent-alpha so bar fades do not stack; plate recycle resumes settled (no re-arrive). Unlock/toggle-off restores the reactive reticle. Not `Animations.lua` (reticle cast feedback only).
- **Cast feedback:** Animations outer `OnUpdate` (one motion); terminals via `CM.NotifyCrosshairCastTerminal`; gated by `crosshairCastFeedback`.
- **Assisted Combat matching:** short recent-suggestion cache — `GetNextCastSpell` often advances before `UNIT_SPELLCAST_SUCCEEDED`.
- **FlipBook / atlas VFX:** ship rows/cols/frames/duration next to the atlas constant in the owning Lua file (see `AssistedHighlight/Motion.lua` for `UF-RogueCP-Slash-Blue`). `C_Texture.GetAtlasInfo` does **not** return FlipBook grid layout. To discover: Blizzard UI source FlipBook XML, other retail addons calling `SetFlipBookRows/Columns/Frames` on the same atlas, then confirm in game. Do not vendor wow-ui-source trees or atlas catalogs into this repo.
- **Controller:** while ours is shown, `CM.DisplayCrosshair` fades Forever's own `GamepadReticle` (alpha 0, never hidden: Blizzard re-shows it on every switch to the controller UI) and gives it back when ours goes / `HideCrosshairFrame`. Keybind badges: `Keybinds.FormatKeybindText` turns pad keys into the connected pad's button glyphs via Forever's `InputIconTextureSetUtility` (Xbox / PlayStation / Switch from the device's label style; text where the client has none). These are client atlases drawn by name on purpose (they must follow the device), the one exception to shipping TGAs. `Keybinds.PickBindingKey` prefers a pad key while the pad is in use; a spell on Forever's controller action bars maps storage slot → page / bar / button → chord (`GAMEPADACTIONBUTTON1-8` + `GAMEPADLEFTMOD` / `GAMEPADRIGHTMOD`), lowest page first.
- **Options preview:** Crosshair tab → `CM.SetCrosshairOptionsPreview` via tab `onSelect`/`onDeselect`; do not reuse mouselook-gated Show/Hide.

**In-game checks:** cast feedback and Assist cast-success in the open world and in a dungeon (no errors from secret cast GUID compares; no double fire from assisted action + `UNIT_SPELLCAST_SUCCEEDED`; rapid Single-Button Assistant presses don't spam it); Target Lock lock / cycle / unlock in an instance; Forever with a controller: one reticle (Blizzard's faded), Assist badge shows the right pad chord / glyph set for Xbox and PlayStation pads, back to key text on mouse / keyboard; the Situational Appearance with both slots hidden hides the reticle while its condition holds.
